SLIDE 3
PART 1 · ASSEMBLY CODE
mov_avg.s: avoiding intermediate overflow
1 · START WITH THE PERCENTAGE FORMULA
output = [α·x + (100−α)·y] / 100
x = new, y = old. The products can overflow int32 for large inputs.
2 · DERIVE THE OVERFLOW-SAFE FORM
x = 100x₁ + x₂ 
(x₁ = x/100, x₂ = x%100)
y = 100y₁ + y₂ 
(y₁ = y/100, y₂ = y%100)
output = [α·x + (100−α)·y] / 100
= [α(100x₁+x₂) + (100−α)(100y₁+y₂)] / 100
= α·x₁ + (100−α)·y₁ + [α·x₂ + (100−α)·y₂] / 100
= Q + R/100
Q = α·x₁ + (100−α)·y₁
R = α·x₂ + (100−α)·y₂
3 · SAFETY TAKEAWAY
Dividing each input by 100 removes about 7 bits before multiplication. Q stays in signed 32-bit range and |R| ≤ 9900, so every intermediate value fits in int32.
ewma_filter · steps 2 and 3
@ r12 = 100
@ x = 100x₁ + x₂
SDIV r4, r0, r12
MUL r5, r4, r12
SUB r5, r0, r5
@ r4 = x₁, r5 = x₂
@ y = 100y₁ + y₂
SDIV r6, r1, r12
MUL r7, r6, r12
SUB r7, r1, r7
@ r6 = y₁, r7 = y₂

SLIDE 5
PART 1 · ASSEMBLY CODE
mov_avg.s: matching C signed truncation
THE PROBLEM, WITH NUMBERS
Q = −5, R = 20
C: trunc((−500 + 20) / 100) = −4
Separated: −5 + trunc(20 / 100) = −5
Off by 1: the result must be nudged toward zero.
BRANCH RULES
Zero remainder, or matching signs: no correction
Positive remainder, negative result: add 1
Negative remainder, positive result: subtract 1
ewma_filter · step 8
@ r1 = leftover remainder
CMP r1, #0
BEQ final_return
BGT remainder_positive
@ negative remainder
CMP r0, #0
BLE final_return
SUB r0, r0, #1
B final_return
remainder_positive:
CMP r0, #0
BGE final_return
ADD r0, r0, #1

SLIDE 6
FEATURE EXTRACTION
From filtered axes to physical motion
Magnitudes reduce dependence on which sensor axis happens to align with the movement.
Accelerometer
BSP gives mg
mg × 9.80665 / 1000
→ m/s²
Gyroscope
BSP gives mdps
mdps / 1000
→ °/s
|A| = √(Ax² + Ay² + Az²)
|G| = √(Gx² + Gy² + Gz²)
At rest |A| is near 9.81 m/s²: gravity is not subtracted.
Low |A|
Loss of support, free-fall-like phase
High |A|
Impact, rapid deceleration
High |G|
Rotation evidence
2 ms poll target, 52 Hz sensor ODR:
 polling faster than the sensor updates can reread the same sample.

SLIDE 11
EDGE → NETWORK
How one telemetry update leaves the STM32
MAIN LOOP
Snapshot
main.c copies the newest processed values
INTERRUPT
SysTick flag
Every 1000 ms it raises a request flag
MAIN LOOP
Process()
Sees the flag, takes the latest snapshot
MAIN LOOP
JSON + \r\n
One record, ended by a newline
MAIN LOOP
SendData()
Over SPI3 to the Wi-Fi module, TCP :2028
The interrupt schedules work. Transmission happens in the main loop.
HAL_SYSTICK_Callback() only sets telemetry_requested. ProjectWifi_Process() makes the blocking WIFI_SendData() call, so no TCP work runs inside an ISR.
A SEPARATE INTERRUPT: WI-FI DRDY
DRDY pin → EXTI → SPI_WIFI_ISR()
Tells the SPI driver the module has response data ready. It does not schedule the 1 Hz publish.
One record carries:
 sample number, fall state, filtered accel and gyro XYZ, |A| and |G|, 5-second min and max (once a window completes), and the environment block: valid, timestampMs, temperatureC, humidityPct.

SLIDE 12
NETWORK
Wi-Fi connection state machine
Startup path
Wait 1 s, initialise the module, join the hotspot, open TCP.
Fails at startup
DISABLED until reset. Sensing and local alerts carry on.
Fails later
Retry TCP after 2 s. Second failure in a row: rejoin the hotspot every 30 s.
After recovery
Sends the latest snapshot. Nothing is buffered or replayed.
